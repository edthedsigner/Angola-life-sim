# World layout and building architecture — proposal (not implemented)

Nothing here changes the game. The map, `world.json` and the server are untouched. The images are generated by
`tools/proposal/world_layout.py` and `tools/proposal/building_examples.py`; edit the layout data at the top of the first script
and re-run to iterate. `world_plan.png`, `world_zones.png` and `world_iso.png` are drawings, not engine captures.

| File | Shows |
|---|---|
| `world_plan.png` | Top-down plan: terrain, roads, buildings (solid = built, hatched = reserved plot), props |
| `world_zones.png` | Neighbourhoods, road hierarchy, dead ends, pedestrian routes, gathering points, expansion |
| `world_iso.png` | The same data in the game's projection |
| `building_examples.png` | Exterior footprint next to the independent interior, same scale, linked by doors |
| `interior_in_place_mock.png` | Mock-up (two real engine captures composited) of an interior opening at the building's map position |
| `scale_audit_casa.png` | Engine captures from the scale audit |
| `world_layout_stats.json` | Tile counts, walking times, validation results |

## 1. Dimensions: 128 × 96 tiles (256 × 192 m)

Measured inputs: a player walks 2.43 tiles/s; a desktop screen at default zoom shows about 225 tiles.

* **Walking times** (computed on the layout): square → shops 3–7 s, square → homes 11–17 s, square → market 21 s,
  market → football pitch 33 s, west → east along the avenue 53 s. Daily trips stay under 25 s; the far corners take 30–45 s.
* **Density:** 12,288 tiles ≈ 55 desktop screens. With 50 players and about half indoors, the ~25 outdoors would be one per two
  screens if spread evenly, so the map relies on ten gathering points (below). Doubling the map again would halve that and feel empty.
* **Composition:** roads 14 %, building footprints 4 % (41 plots), the rest is varied ground. No surface exceeds 18 %.
* **Growth:** coordinates are signed and four edges are open (avenue west and east, north exit, outskirts track), so
  neighbourhoods can be added without moving anything.

## 2. Neighbourhoods
Boundaries come from noise-distorted regions, not rectangles, so areas blend into each other.

| Area | Purpose | Ground |
|---|---|---|
| Centro comercial | shops, restaurant, offices, square (spawn) | concrete, paved sidewalks, gravel parking |
| Mercado informal | stalls, street vendors, warehouse | compacted dirt, bare soil, broken sidewalk |
| Zona em construção | fenced building site, empty plots | bare soil, gravel, dry grass |
| Bairro residencial | houses with yards, alleys, school | dirt lanes, mixed yards, grass |
| Zona dos prédios | apartment blocks, parking, courtyards | concrete aprons, dirt, grass |
| Periferia | open land, trees, football pitch, track | grass, dry grass, soil |
| Areal | sand and scrub beyond the drainage channel; future houses | sand, dry grass |

## 3. Roads
* **Main:** Avenida — asphalt, 4 tiles, curves across the map; sidewalks only where there is commerce, gravel shoulders elsewhere.
* **Secondary:** Rua do Comércio (asphalt, 3 tiles, north exit); Rua dos Prédios (asphalt, dead end with turning circle).
* **Dirt streets:** Rua do Bairro (dead end in a small yard), Rua do Mercado (ends at the building site), outskirts track.
* **Alleys:** one links Rua do Bairro to the avenue; two are dead ends.
* **Pedestrian only:** market passage, apartments → pitch shortcut, two paths over the drainage channel (footbridges), school path.
* Every door gets a footpath to the nearest street, generated from the data.
* The drainage channel is the one non-walkable ground type; it can only be crossed at the footbridges.

## 4. Buildings on the map
* Existing (keep their current exteriors): Mercearia 5×4 (2 floors), Escritório 4×5 (3), Restaurante 3×4 (2), Casa Mussulo 3×4 (1).
* New in this milestone: Prédio Kilamba 6×4, 3 floors, 6 apartments, on Rua dos Prédios.
* Reserved plots (drawn hatched, not built now): Farmácia, Padaria, Banco, Bar, Oficina, Armazém, Escola, Salão, Prédios B and C,
  26 houses. Housing: 7 units now, 45 with every plot built.
* Doors can only be on the south and east faces (the two faces the camera sees), so buildings sit north or west of the street they
  face. The south side of the avenue therefore carries vendors, parking and walls instead of shop fronts.

## 5. Exterior and interior are separate representations
```jsonc
"buildings": [{
  "id": "predio_kilamba", "name": "Prédio Kilamba", "type": "apartment",
  "exterior": {                       // what occupies the shared map
    "c0": -32, "r0": 8, "w": 6, "d": 4, "floors": 3, "palette": "green", "roof": "flat", "shopfront": false,
    "entrances": [{"id": "frente", "face": "side", "i": 2, "to": {"floor": 0, "edge": "v:4:5"}}]
  },
  "interior": "predio_comum",         // id in "interiors" (or an inline definition)
  "units": [                          // residential units; a house has exactly one, covering the whole interior
    {"id": "0A", "floor": 0, "door": "v:0:2", "interior": "apartamento_t1", "rental": "apartamento_t1"},
    {"id": "0B", "floor": 0, "door": "v:4:2", "interior": "apartamento_t1", "rental": "apartamento_t1"}
  ]
}],
"interiors": {                        // playable spaces, designed for the building's purpose; reusable as templates
  "predio_comum":   {"floors": [/* w, l, walls, openings, rooms, furniture */], "stairs": [/* lo, x, y, len */]},
  "apartamento_t1": {"floors": [/* … */], "stairs": []}
}
```
* Existing fields (`floors`, `walls`, `openings`, `furniture`, `stairs`, activities on furniture) keep their format; they move under
  `interiors`. The current four buildings convert mechanically.
* Server start-up validation: exterior floor count equals interior floor count; each exterior door maps to a perimeter edge on the
  same face; ground-floor area between 2× and 5× the footprint; plus the existing checks (connected floors, furniture, stairs).
  All four current buildings are at 4.0×; the apartment block is 4.3× counting its two ground-floor flats.

## 6. Continuous interiors without 1:1 scale
* Entering opens the interior **at the building's position on the map**, anchored on the door used, with the street dimmed around it
  (`interior_in_place_mock.png`). No black screen, no void.
* Floors are drawn stacked 48 px apart at their real relative positions: current floor solid, floors above see-through, floors below
  showing their front walls. Visual only.
* Stairs are walked: the server changes the player's floor when they reach the landing; no fade, no jump on screen.
* The anchoring is a drawing offset in the client. **Server coordinates and zones do not change, so no saved position needs
  migrating.**

## 7. Residential units
* Zones: common areas stay `b:<building>:<floor>`; each unit is its own zone `u:<building>:<unit>`, entered through its door in the
  corridor. A unit's furniture, storage and state are only sent to players the server has let in.
* Lease per unit: tenant, expiry, furniture, storage, visitor permissions. One active lease per character; the data model keeps a
  list so more can be allowed later.
* Invites target a unit. Visitors cannot move or take anything unless a permission says so (default: none).
* **Legacy Casa Mussulo tenancy:** Ed and GC keep their leases untouched (same expiry, no money moved). While any legacy lease is
  active the house accepts no new tenant; when only one remains, that player is the sole tenant with the original time left.

## 8. Technical notes
* Ground becomes data (`terrain` in `world.json`: surface per tile, generated from the layout) drawn in chunks instead of one node
  per tile; 12,288 single-tile nodes would be too heavy for phones.
* New art needed: tiles for dirt, soil, sand, gravel, concrete, channel, footbridge; props for stalls, poles, fences, cars, goals.
  Existing sprites are not resized.
* Pathfinding over 12,000 cells needs Godot's built-in grid A* instead of the current script loop.
